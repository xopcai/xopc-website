# Agent 产品官网调研与 xopc 优化建议

调研日期：2026-10-21。对象：Work Agent、Personal Agent、桌面 Agent 和相邻的工作自动化产品。

## 结论

xopc 有明显优化空间，首要机会是重新安排“产品是什么 → 能做成什么 → 为什么值得长期使用 → 如何开始”的信息顺序。

现有官网有个性、有故事，也已经拥有真实演示、可编辑成果、场景库、隐私说明和多端下载。问题在于首页首先花较长篇幅建立情绪共鸣，用户需要继续阅读才能确认它实际能做什么。建议保留温暖的品牌气质，同时提前展示真实产品、成果与上手条件。

建议验证的定位是：**为独立工作者打造，理解个人上下文、交付工作成果，并持续接着做的个人 AI 工作伙伴。** 这是定位假设，尚未经过用户访谈和转化实验验证。

## 方法与边界

- 直接读取官方首页、产品页与必要的官方入门页；以当前可读取内容为准，不以搜索摘要中的旧版文案为准。
- 核对本仓库首页、Ada、使用场景、下载和分析事件实现，区分“已存在但位置不佳”和“需要新增”。
- 浏览器多次打开页面超时，未完成可靠的截图、响应式或实际交互测试。视觉建议依据源码中的布局、样式和内容结构，不能当成实际屏幕验收结果。
- 未登录竞品、未测试竞品实际任务，也未取得 xopc 生产转化数据。所有竞品能力均指官网宣称；不据此认定实际效果、性能或安全性。
- 本文为研究与方案，未更改产品页面或发布线上内容。未使用数字评分，以免把主观观察伪装成测量。

## 1. 九个有效样本

### Claude Cowork：把“交办后得到什么”讲清楚

官方页先交代目标、文件与工具、供用户审核的成品，再展示周期报告、表格处理、批量审阅等场景；付费计划要求靠近下载入口。安全说明围绕可访问范围、重要操作和用户控制展开。[官方产品页](https://claude.com/product/cowork)

值得借鉴：每个场景都能回答“给它什么、它做什么、我回来检查什么”。xopc 可以用真实表格和演示稿说明交付，而不只用聊天回答说明理解。

应注意：当前页顶部已经提示 Cowork 正在并入 Claude。产品命名在变化，不能照搬旧文章中的信息架构。

### Manus：按用户想要的产物组织入口

首页直接提供 Slides、Website、Design 等任务方向，并连接对应功能页、价格和使用入口。它把“要做什么”放在解释底层 Agent 机制之前。[官方首页](https://manus.im/)

值得借鉴：xopc 首页挑选少量代表成果，直接连接已有场景库。用户不用先掌握 Project、Task、Runtime 等概念。

不宜照搬：xopc 需要安装和连接模型，不应放一个看似能在线执行、实际上只能跳转下载的输入框。已有 `xopc://chat/new` 草稿入口可以复用，但应明确需要安装。

### OpenClaw：把自主权和熟悉的使用入口说具体

首页把机器归属、开源与数据控制放在明显位置，用邮件、日历及已有聊天软件解释日常用途，并提供多种安装方式、社区反馈和文档。[官方首页](https://openclaw.ai/)

值得借鉴：本地优先需要解释成用户收益，例如资料由谁保存、模型由谁选择、记忆能否修改。也要告诉用户能从哪里继续使用。

竞争含义：本地、记忆、模型选择和多入口本身已经不是 xopc 独有的传播优势。需要用具体工作过程证明组合价值。无需复制很长的反馈墙或密集安装命令。

### Lindy：用熟悉的工作现场建立购买理由

当前首页强调 AI teammate，通过工作消息、处理步骤、成果与后续操作演示实际工作；同时展示工具连接、日程执行、可编辑记忆、试用条件及用户反馈。[官方首页](https://www.lindy.ai/)

值得借鉴：把“输入 → 执行 → 成果 → 修改”放在同一个故事中。Ada 也可以有亲近感，同时明确承担任务。

不宜照搬：官网中的示例耗时、经营指标和客户背书不等于经过独立验证的效果。xopc 不应借用这些数字或用未知用户的标志装饰页面。

### Perplexity Computer：解释持续工作，也解释具体环境

Computer 产品页强调从任务到后台工作再到持续迭代；Personal Computer 的 Windows 页面进一步交代本地文件、桌面应用、浏览器和授权范围。[Computer 产品页](https://www.perplexity.ai/en-GB/products/computer)、[Windows 产品页](https://www.perplexity.ai/en-GB/hub/products/computer-for-windows)

值得借鉴：xopc 可以展示“过一段时间再回来继续”的价值，但必须交代运行条件。手机能继续访问并不自动等于电脑离线后任务仍会执行。

竞争含义：跨端与后台推进正在成为常见叙事。应展示同一个目标、资料、决定和结果如何延续，而不是只排列设备图标。

### WorkBuddy：中文用户一眼能理解的办公成果

官网直接说明产品类别与任务交付，按研究、文档等工作组织展示，并提供清晰的桌面、移动和在线入口。其官方腾讯页面也能确认产品归属。[官网](https://www.workbuddy.cn/)、[腾讯官方介绍](https://cloud.tencent.com/act/pro/workbuddy)

值得借鉴：中文表达要具体到报告、表格、演示稿等交付物，让用户快速识别适用场景。

不宜照搬：xopc 的个人上下文和长期使用价值值得保留，没必要完全变成泛办公工具。该站合规与安全声明也不能作为 xopc 的可用文案。

### QoderWork：把本地桌面工作讲成完整的使用过程

官网组织自然语言任务、文件产出、工具生态及移动控制；官方快速入门把安装、登录、工作区、首个任务和产物串成可跟随的流程。[官网](https://qoderwork.com/)、[官方快速入门](https://docs.qoder.com/zh/qoderwork/quick-start)

值得借鉴：下载不是终点。xopc 应让用户知道安装后还要连接模型、准备什么资料，以及第一次可以得到什么。

来源处理：搜索中存在多个名称相近域名；本次仅采用官方文档所指向的 `qoderwork.com`，不采用近似域名的产品或隐私声明。

### Notion Agents：同一品牌下的两种使用方式可以解释清楚

页面明确区分按需协助个人工作的 Notion Agent 与按触发条件持续运行的 Custom Agents，并解释它们共享的工作环境、各自权限及使用条件。[官方产品页](https://www.notion.com/product/agents)

值得借鉴：xopc 和 Ada 的关系要在前段直接说明。用户应知道 Ada 属于同一个应用，而不是先理解两个产品再做选择。

### Gumloop：把能力落实为工作过程与运营控制

当前官网把 Agent、连接器、技能、成果及运行管理放在实际业务任务中呈现，并展示人工接管与执行记录。[官方首页](https://www.gumloop.com/)

值得借鉴：安全控制可以有具体界面证据，例如资料范围、等待确认、执行记录。抽象的“安全可控”不足以解释边界。

不宜照搬：其团队治理与企业管理信息较重，xopc 首页无需承担完整平台说明书的任务。

补充筛选：Huxe 当前官网已经公告停止继续开发，未作为在售 Personal Agent 官网范式。[官方公告](https://www.huxe.com/)

## 2. 对 xopc 最有价值的竞争判断

### Work Agent 与 Personal Agent 的官网表达正在交汇

个人上下文、记忆、工具执行、后台任务和跨设备使用，已经同时出现在多个样本中。因此，把首页分成“一个有温度的个人 AI”和“一个能工作的 Agent”，容易让用户觉得需要在两者间选择。

更适合 xopc 的串联方式是：**理解我的背景 → 交办一件事 → 得到可用成果 → 下次沿着同一件事继续。** Ada 解释人与 AI 如何建立上下文，工作空间解释事情如何完成，两者服务于同一个承诺。

这不是已被证明的独占能力，而是值得用真实案例建立的品牌重点。

### 用户需要的证据比能力列表更具体

从多个样本归纳出一张可复用的“案例证据表”：

| 用户问题 | 页面应该提供的证据 |
| --- | --- |
| 可以替我做什么？ | 清晰任务名称和最终成果预览 |
| 需要我提供什么？ | 输入资料、授权和配置条件 |
| 真的完成了吗？ | 可打开的结果、来源或执行记录 |
| 做错了怎么办？ | 检查、修改、停止及确认的实际方式 |
| 我离开后怎么办？ | 保存了什么、在哪里继续、运行依赖是什么 |
| 开始会不会很麻烦？ | 安装、模型连接、首个任务的真实步骤 |

不要求每个案例覆盖所有问题，但主案例应该连贯覆盖大部分。

## 3. 官网现状：值得保留的部分

1. **有品牌辨识度。** 纸张、便签、Loopi 和柔和的语言形成了明确设计方向；无需因为竞品强调生产力就全部推翻。实际视觉效果仍需截图验收。
2. **主动区分情境示例与真实演示。** 四段故事明确写明非真实执行，Work 短片承担真实产品说明；这种诚实值得保留。
3. **已有真实素材。** Work v2 中文约 63 秒、英文约 68 秒；Ada 页已有真实对话、委托和结果修改截图。
4. **已有 36 个场景。** 涵盖规划、整理、研究、创作、开发、自动化，并提供准备条件、确认边界、证据说明和草稿深链。无需再造一套场景系统。
5. **隐私措辞有边界。** 已区分核心状态本地保存与云模型处理请求上下文，避免把“本地优先”等同于完全离线。
6. **已有转化分析基础。** 下载、平台选择和场景入口等事件已经存在，可以在其上完善验证。

核对来源：[首页](https://xopc.ai/zh)、[Ada](https://xopc.ai/zh/ada)、[场景库](https://xopc.ai/zh/use-cases)，以及本地 `components/landing-page.tsx`、`lib/landing-story-copy.ts`、`lib/ada-copy.ts`、`lib/use-cases.ts` 和 `content/work/manifest.json`。

## 4. 主要优化空间

### P0：首屏的产品解释偏抽象

“一个人，也能让想法走得更远”和“记住来时的路，接住未完成的事”有情绪价值，但未直接说明运行环境、典型任务与成果。英文副标题同样偏抽象。

建议：品牌主标题可以保留，副标题承担具体解释；或者测试更明确的主标题。首屏同时给出真实产品预览和观看 Work 演示的入口。

**保留现主标题的文案草案：**

> 一个人，也能让想法走得更远。
>
> xopc 是运行在你电脑上的个人 AI。记住项目背景，整理资料、分析表格、制作汇报，下次接着做。
>
> 下载 xopc　｜　观看真实演示 · 约 1 分钟
>
> macOS / Windows / Linux · 核心状态本地保存 · 需连接模型服务

**另一组可测试主标题：**

> 记得你的目标，也帮你把事做完。

英文草案：

> A personal AI that remembers your context and moves work forward.
>
> Work with your files, analyze spreadsheets, and build presentations on your computer. Pick up where you left off.

文案不是实测胜出版本。正式使用前应核对平台状态与每项能力，不添加未经验证的免费、速度、离线或全天运行承诺。

### P0：真实成果出场太晚

首页源码顺序是 Hero → 四章故事 → Work 短片 → 信任说明 → 下载。增强桌面布局中，每章有 `min-height: 78vh`，四章最小高度合计约 3.12 个视口，还不含首屏、故事引言和其他间距。这是 CSS 推导，不是用户实际滚动距离实测。

建议：把 Work 短片或真实静态成果移到首屏附近。四章故事可以保留完整版本，但首页先给一个紧凑摘要或允许主动展开。默认读者不应看完整个故事才知道成果长什么样。

展示顺序可调整为：先看到表格和汇报结果 → 理解从什么资料生成 → 查看如何修改 → 再理解上下文如何延续。

### P0：Ada 有成为“主要用来聊天”的认知风险

Ada 页现有“今天有点忙 / 有个新想法 / 想聊一会儿”等入口，以及“慢慢说，我在听”的标题，能建立亲近感；但交办和产出要在后面才展开。

建议保持名称和语气，补一条明确的职责说明：

> Ada 是 xopc 里的个人 Agent。和你理清目标，也能接下任务，把结果带回来。

互动提示可以测试为“理清这周重点 / 把想法变成计划 / 继续上次的事”。这只是官网演示提示，不应伪装成真实任务执行。

导航可考虑显示“Ada · 个人 Agent”，降低陌生名称的理解成本。现有“已包含在 xopc 桌面应用中”说明值得保留，并尽早出现。

### P0：下载前的决策信息还不够完整

首页下载区已提示连接模型，Ada FAQ 也有入门说明；但用户仍需理解：软件是否收费、模型费用由谁承担、怎样连接模型、手机是否依赖电脑、电脑离线时会怎样。

建议首页增加精简的“开始前你需要知道”，并提供独立的开始使用入口。先核实真实规则，再发布答案。无需为了有价格页而设计不存在的套餐。

把第一次任务收敛成一个容易成功的例子：使用一份示例材料，整理成可检查的一页文件；不要一开始要求连接邮箱、日历和多个服务。具体时间承诺应在实际计时后决定。

### P1：已有场景库，缺少首页上的精选与结果证据

现有场景库的信息比首页更具体。建议从中选三个代表方向放到首页：资料到汇报、个人目标到周计划、旧项目到下一步。

每项只展示：一句需求、必要准备、一张真实结果、一个查看案例按钮。随后进入现有场景库或实战教程。

“已提供提示词和能力说明”与“这个案例经过端到端验证”应区分。建议为首页精选案例记录验证日期、应用版本、输入材料、必要配置和检查方式；不必立即给全部 36 项补齐重型案例。

### P1：信任说明应有界面支撑

现有本地状态、云模型上下文和可修改记忆的解释已经不错。可以选一个真实界面证明“我能控制什么”，例如可修改的记忆或等待确认的任务。

不要把“有变更记录”扩写成“所有操作都能撤销”，也不要把“核心状态本地保存”扩写成“资料永不出电脑”。

### P1：品牌介绍与搜索入口可承担不同任务

首页继续讲统一品牌，场景页负责承接“AI 表格分析 / 资料生成汇报 / 持续项目助手”等具体需求。优先把三个已验证案例做成独立、有真实成果和上手指引的内容，再扩展更多页面。

现有 product-map、场景库、教程和博客均可复用。不要为了关键词批量生成只替换标题的页面，也不要先急于上线未经核验的竞品功能对比表。

## 5. 推荐首页顺序

| 顺序 | 内容 | 解决的问题 | 可复用素材 |
| --- | --- | --- | --- |
| 1 | 品牌标题、具体副标题、下载与真实演示按钮 | 这是什么，适不适合我 | 现有 Hero、下载解析 |
| 2 | 真实产品与成果预览 | 它能做成什么 | Work v2、真实截图 |
| 3 | 三个精选任务 | 我今天可以交办什么 | 使用场景库、实战教程 |
| 4 | 从个人背景到执行交付 | Ada 与工作空间如何协作 | Ada 对话、委托、修改素材 |
| 5 | 同一件事接着做 | 为什么值得持续使用 | 四章故事的精简版本 |
| 6 | 数据、记忆与确认边界 | 我能控制什么 | 现有信任区与隐私说明 |
| 7 | 开始步骤、费用与运行条件、平台下载 | 下载后怎么成功开始 | 下载组件、入门文档 |

这不是要求增加七个大型区块。应压缩现有故事的默认阅读长度，避免把新内容不断叠加到旧长页上。手机优先保证清晰静态结果和完整操作入口，交互动效作为增强。

## 6. 可立即确认的测量缺口

### Ada 下载事件未接入完整链路

- `components/ada-page.tsx` 两个下载按钮声明 `data-product-event="ada_download_clicked"`。
- `lib/product-events.ts` 的 `PRODUCT_EVENT_NAMES` 不包含这个事件。
- `components/landing-analytics.tsx` 的声明式点击监听只接受白名单内名称。
- Ada 页面本身也未挂载 `LandingAnalytics`；全局 `SiteAnalytics` 当前只发送页面浏览事件。

因此，仅凭这些声明无法记录 Ada 下载点击；直接打开 Ada 时也缺少对应点击监听。这是静态代码检查结论，未查询线上数据库。修复时应同时处理事件注册与监听范围，避免重复监听或只补名称而仍然收不到点击。

### 无法直接判断真实演示的贡献

检查到的视频按钮没有显式的观看开始、完成事件；事件列表也缺少这类事件。当前下载指标不足以说明“用户有没有看真实演示，以及看过之后是否更愿意开始”。

建议记录演示打开、实际开始播放和完成，并区分 Work/Ada、语言与入口。打开弹窗不等于观看；完成率用实际开始播放的会话作分母。

### 下载请求不等于成功激活

现有 `download_started` 是安装包请求侧信号，不能证明安装或完成首个任务。网站可以先衡量下载漏斗；如果需要产品激活指标，应在产品侧另行设计隐私适当、明确告知的数据链路，不能凭网站事件推断。

## 7. 分阶段执行与验证

### 第一阶段：先用现有素材提高理解速度

- 补具体首屏副标题，把真实演示入口前移。
- 让真实成果在故事前出现，压缩故事默认长度。
- 明确 Ada 属于同一应用，以及其交办职责。
- 补经过核实的模型连接、费用承担与手机依赖说明。
- 修复 Ada 点击事件，补 Work/Ada 观看测量。

主要涉及：`components/landing-page.tsx`、`lib/landing-story-copy.ts`、`components/landing-story.module.css`、`lib/ada-copy.ts`、`components/ada-page.tsx`、`components/landing-analytics.tsx`、`lib/product-events.ts` 和视频组件。正式改代码前按仓库要求读取当前 Next.js 本地指南。

### 第二阶段：证明长期使用价值

- 将三个精选场景做成有真实输入、成果与修改过程的案例。
- 补“第二天回来继续”和“手机查看同一结果”的真实证据与运行条件。
- 把首页、Ada、场景和教程接成可跟随的首个任务路径。

### 第三阶段：依据数据决定是否扩大改版

| 假设 | 建议验证方式 | 观察结果 |
| --- | --- | --- |
| 现首屏偏抽象 | 让目标用户短时间阅读后，用自己的话解释产品 | 是否理解桌面应用、任务交付、模型连接和 Ada 关系 |
| 真实成果前移有帮助 | 基线与新版比较，按语言、设备和来源分组 | 演示实际播放、有效下载请求，以及可取得的首任务成功反馈 |
| Ada 过于像陪聊入口 | 比较不同职责说明与提示文案 | 用户能否举出可交办的任务，是否进入相关场景 |
| 下载后配置有阻力 | 跟随目标用户完成首次安装与模型连接 | 具体失败环节和疑问，而不只看下载量 |

流量足够时做随机实验；流量不足时先做少量目标用户的理解测试与上手观察，再看分组趋势。预先定义指标和观察条件，不因一两天点击率波动宣布成功。

首屏曝光、下载区曝光、CTA 点击、安装包请求应使用各自明确的分母。尤其要区分“用户主动去下载区”和“只是滚动到下载区”。

## 建议决策

优先批准的方向应是：**保留品牌风格，先调整信息结构和真实证据的位置。** 暂不需要更名、移除 Loopi、另造一套 Work 产品，或重做完整视觉系统。

最值得做的第一轮是一个可以与现版对照的完整首页版本：用户先理解能交办什么、看到真实结果，再感受到个人上下文与持续协作的价值。
